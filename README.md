# Практическая работа №1. Первый проект: GitHub и IDE

> Дисциплина: «Разработка клиент-серверных приложений»

## Зачем это

Первая практика не про сложный код. Она про **рабочий процесс**: как получить проект, открыть его в среде разработки, запустить, изменить и отправить результат обратно на GitHub.

Всё, что нужно, — это 10 шагов ниже. Если ты раньше не работал ни с IDE, ни с GitHub, инструкция написана ровно для такого случая: иди по порядку и не пропускай шаги.

**Что получится в итоге:** у тебя есть собственный репозиторий в организации курса, в нём проект, который печатает `Hello World`, и в истории — твой коммит.

## Словарик

Прочитай один раз — дальше эти слова будут встречаться постоянно.

- **Репозиторий (репо)** — папка с проектом, которую GitHub хранит у себя. У неё есть адрес вида `https://github.com/имя/проект`.
- **Клонировать** — скачать репозиторий с GitHub к себе на компьютер, чтобы работать с ним в IDE.
- **Коммит** — «сохранение» изменений на твоём компьютере.
- **Push (пуш)** — отправить сделанные коммиты обратно на GitHub.
- **IDE** — среда разработки, программа, в которой пишут код (в этом курсе — OpenIDE).
- **Токен** — длинный набор символов, который заменяет пароль. Для доступа к коду GitHub обычные пароли не принимает.
- **Организация** — общий аккаунт GitHub на всю группу: туда преподаватель кладёт шаблоны, а вы — свои работы.

> **Коммит ≠ push.** Коммит сохраняет изменения только у тебя на компьютере. Чтобы их увидел преподаватель, нужен push.

## Шаг 1. Прими приглашение в организацию

Преподаватель отправит на почту, привязанную к твоему аккаунту GitHub, письмо с приглашением в организацию курса.

1. Открой письмо от GitHub — в теме будет что-то вроде *«… invited you to join …»*.
2. Нажми в письме кнопку **View invitation** (может называться **Join**).
3. Откроется страница GitHub — нажми зелёную кнопку **Accept invitation**.

Проверить результат: нажми на свою аватарку в правом верхнем углу → **Your organizations**. Организация курса должна быть в списке.

> Письма нет — посмотри в «Спам». Приглашение можно принять и без письма: открой `https://github.com/java101-ranepa-26-27/invitation`, уже будучи залогиненным в GitHub.

**Без этого шага следующий не сработает:** создавать репозиторий в организации может только её участник.

---

## Шаг 2. Создай свой репозиторий из шаблона

В организации лежит репозиторий-шаблон — готовая заготовка проекта. Редактировать её нельзя: ты создаёшь **свою копию**, с которой и будешь работать.

1. Открой страницу шаблона: **https://github.com/java101-ranepa-26-27/java101-template**
2. Нажми зелёную кнопку **Use this template** → **Create a new repository**.
3. Заполни поля на открывшейся странице:
   - **Owner** — раскрой список и выбери организацию **java101-ranepa-26-27** (а не свой личный аккаунт).
   - **Repository name** — имя твоего репозитория. Возьми что-то узнаваемое, например `java101-ivanov` (фамилия латиницей). Имя должно быть уникальным внутри организации.
   - **Description** — можно оставить пустым или написать «Практика 1».
   - **Visibility** — оставь **Public**, если преподаватель не сказал иначе.
4. Нажми **Create repository**.

Готово: у тебя есть личный репозиторий с файлами заготовки. Его адрес — тот, что в адресной строке браузера; он понадобится на Шаге 4.

**Почему Owner — организация, а не ты лично?** Так работы всей группы лежат в одном месте и преподаватель видит их сразу. Права на запись в свой репозиторий у тебя есть, потому что ты участник организации.

- Нет организации в списке **Owner** → не принято приглашение, вернись к Шагу 1.
- Пишет **«name already exists»** → такое имя в организации занято, добавь к нему инициалы или номер группы.

## Шаг 3. Установи IDE

Скачай **OpenIDE** — бесплатную среду разработки: https://openide.ru/download

Установи её как обычную программу и запусти хотя бы раз, чтобы убедиться, что она открывается.

Заодно проверь, что установлен **git** — https://git-scm.com/downloads.

---

## Шаг 4. Клонируй свой репозиторий в IDE

1. На странице **своего** репозитория (из Шага 2) нажми зелёную кнопку **Code** → вкладка **HTTPS** → значок копирования.
   Ссылка выглядит так: `https://github.com/java101-ranepa-26-27/java101-ivanov.git`
2. В IDE открой **File → New → Project from Version Control…**
3. Вставь скопированную ссылку в поле **URL**. Папку для проекта IDE подставит сама.
4. Нажми **Clone**.

### Если IDE просит войти в GitHub

GitHub не принимает обычный пароль от аккаунта — вместо него нужен **токен**.

1. В окне входа нажми **Generate token** (может называться **Generate…**).
2. Откроется страница GitHub «New personal access token». **Заполнять на ней ничего не нужно** — все поля (Note, Expiration, Scopes) уже подставлены.
3. Найди поле **Expiration** и выбери **No expiration** — чтобы токен не истёк посреди семестра.
4. Пролистай страницу вниз и нажми **Generate token**.
5. GitHub покажет готовый токен — скопируй его и вставь в окно IDE.

> ⚠️ **Токен показывается только один раз.** Сразу сохрани его в менеджер паролей. Посмотреть повторно нельзя — если потеряешь, придётся создавать новый: GitHub → аватар → **Settings** → **Developer settings** → **Personal access tokens**.

Если клонирование прошло успешно, проект появится в левой панели IDE.

## Шаг 5. Настрой Java 21

Проект рассчитан на **Java 21**. IDE может её не найти и подсветить файлы красным либо написать **«no SDK found»**.

1. **File → Project Structure…** (горячие клавиши `Ctrl+Alt+Shift+S`).
2. Слева выбери **Project**.
3. В поле **SDK** нажми **Add SDK → Download JDK…**
4. **Version: 21**, **Vendor: Amazon Corretto** → **Download**.
5. Дождись скачивания, затем **Apply → OK**.

Заодно проверь, что в поле **Language level** стоит 21 (или `SDK default`).

---

## Шаг 6. Запусти программу

1. В левой панели разверни `src → main → java → ru.ranepa`.
2. Двойным кликом открой файл **`Hello.java`**.
3. Рядом со строкой `public class Hello` появится зелёный треугольник ▶ — нажми на него и выбери **Run 'Hello.main()'**.

Первый запуск скачивает Gradle и зависимости, поэтому может занять пару минут — это нормально, просто подожди.

Внизу откроется панель **Run**, и в ней появится:

```
Hello
```

Если видишь `Hello` — окружение настроено правильно.

---

## Шаг 7. Измени код

Файл `Hello.java` всё ещё открыт. Найди строку:

```java
System.out.println("Hello");
```

Допиши в кавычках слово `World`:

```java
System.out.println("Hello World");
```

Запусти программу ещё раз (тот же зелёный треугольник). В консоли должно появиться `Hello World`.

---

## Шаг 8. Сделай коммит

1. Нажми **`Ctrl + K`** (на macOS — `⌘ K`). Откроется окно коммита.
2. В списке изменённых файлов **оставь галочку только на `Hello.java`** — остальные файлы не трогаем.
3. В поле **Commit message** напиши: `добавлен World`
4. Нажми **Commit**.

Изменение сохранено, но пока только у тебя на компьютере — на GitHub его ещё нет.

---

## Шаг 9. Отправь изменения на GitHub

Нажми **`Ctrl + Shift + K`** (на macOS — `⌘ ⇧ K`). Откроется окно push — нажми **Push**.

С этого момента твой коммит виден на GitHub.

---

## Шаг 10. Проверь результат

Открой страницу своего репозитория (ссылка из Шага 2) и обнови её.

Должно быть так:

- в файле `Hello.java` — строка `System.out.println("Hello World");`
- рядом с файлом — сообщение коммита `добавлен World`
- на главной странице репозитория в списке коммитов — твой коммит

Если всё совпало — практика выполнена.

## Если что-то пошло не так

| Проблема | Причина и решение |
|---|---|
| Организации нет в списке **Owner** (Шаг 2) | Приглашение не принято — вернись к Шагу 1 |
| **«Repository name already exists»** | Такое имя в организации занято — добавь инициалы или номер группы |
| IDE пишет **«no SDK found»** | Не настроена Java — см. Шаг 5 |
| При клонировании просит пароль и не пускает | Нужен токен, а не пароль — см. Шаг 4 |
| Потерял токен | Создай новый: GitHub → аватар → Settings → Developer settings → Personal access tokens |
| Первый запуск долго висит на скачивании Gradle | Это нормально, идёт загрузка. Дождись окончания |
| В консоли `Hello` без `World` | Правка не сохранилась — нажми `Ctrl+S` и запусти заново |
| В окне коммита нет ни одного файла | Ты ничего не изменил — вернись к Шагу 7 |
